Four ideas

rounding = 12

One radius, everywhere

The Omarchy shell reads decoration:rounding back out of Hyprland, so bar popups, notifications, the menu, the polkit prompt and the lock screen all round to match. Change one number and the whole desktop follows.

border_size = 0

Depth, not outline

No window frame at all — which is what removes the theme's tinted active-border gradient. Focus is carried by a plain black shadow, so it never fights the wallpaper. Shell controls follow the same rule and state themselves by fill alone.

speed = 2.1

Motion you don't wait for

Three bezier curves, nothing over ~220ms. Windows arrive from 94% and leave a little faster than they came; workspace switching gets a 15% slide that Omarchy ships turned off. Nothing appears out of nowhere — that is the whole job.

soften.status

One icon, not a dashboard

Workspaces and the focused window on the left, the widget row and the clock on the right, nothing in the middle. Status is a single glyph that only changes color when something has actually failed.

Behind the glyph

soften.status is a bar widget, not a monitor. Nothing runs in the background: two systemctl calls and one ss fire when the panel opens and every five seconds while it stays open. Nothing needs root.

Services

Every watched systemd unit that is actually installed, with its live sub-state. Candidates cover the usual databases, container runtimes and web servers; anything not installed is dropped, so the list only shows what this machine really runs. Click a row for systemctl status in a terminal.

Listening

Every listening TCP socket, with the process name where the kernel will tell an unprivileged process. Anything bound off loopback is tagged exposed — the one thing on the page that gets to use the urgent color. 

// add your own units, or change the refresh rate, in shell.json
{ "id": "soften.status", "units": "gitea vaultwarden", "interval": 3000 }

What it writes

Nothing outside this list is touched — fonts included. Your keybindings, monitors, input settings, idle timings and theme are left exactly as they are, and omarchy theme set keeps working, because every file lands in the layer above the active theme.

PathWhat lands there
~/.config/hypr/looknfeel.lua Radius, zero borders, neutral shadow, blur, motion curves
~/.config/omarchy/shell.toml Bar translucency, borderless controls, neutral hairlines on every popup
~/.config/omarchy/shell.json The bar subtree only — layout and widgets
~/.config/omarchy/plugins/soften.status/ The status widget: a manifest, one QML file, one shell script

Putting it back

Every file is copied into backups/<timestamp>/ before it is written, and the paths that did not exist yet are recorded too. Restoring replays both: files copied back byte for byte, created files deleted again. 

./restore.sh          # back to how things were before soften
./restore.sh --last   # undo only the most recent install
./restore.sh --list   # show every backup taken

The first install writes backups/ORIGINAL and never moves it again. That is the one restore.sh defaults to — after a second install, the newest backup describes a machine that already had soften on it, which is not what putting it back means.

Worth knowing

Why the scripts move in a particular order

Mutating a plugin directory while the shell still has that plugin loaded makes it hot-reload, and Quickshell 0.3.0 segfaults on that path — a bad dynamic_cast in IpcHandler::updateRegistration during Repeater regeneration.

So both scripts write a shell.json with the soften widgets dropped first, let the shell settle, and only then swap the plugin directory. Config writes go through a temp file and a rename, so a watcher never reads half a file.
